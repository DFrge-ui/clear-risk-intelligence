# Как честно представить CLEAR на собеседовании

Это материал для подготовки, а не утверждение о твоих уже подтверждённых навыках. Сначала проверь всё описанное самостоятельно. Рассказывай о тех частях, которые действительно понимаешь.

## Короткое описание на английском

“CLEAR is an AI-assisted learning project built around synthetic operational-risk incidents. It takes a CSV file, validates and normalizes the records, explains which rows were excluded, and creates a small review dashboard and management report. The rules are illustrative, not bank policy. I am using this project to learn how a repeatable data workflow works from input to output.”

## Что показать за три минуты

1. Покажи главную страницу. Объясни разницу между общим числом инцидентов, активными случаями и записанными суммами убытков. Суммы не означают экономию, достигнутую тобой.
2. Открой критический активный инцидент. Найди дату, владельца, исходную строку и сработавшие правила.
3. Перейди к Data pipeline. Объясни, почему исходных строк 175, а принятых 168: четыре точных дубликата и три ошибки. Нормализация строк не означает удаление.
4. Загрузи sample CSV и покажи предварительную проверку. До Apply accepted records активный набор остаётся прежним.
5. Примени фильтр и экспортируй отчёт. Его числа соответствуют той же выборке.

## Вопросы, на которые стоит научиться отвечать

**Почему Flask?** Для небольшого Python-приложения достаточно простых HTTP-маршрутов, шаблонов и отдельных функций анализа. Отдельная сборка frontend не нужна. Это выбор для учебного объёма, не заявление о лучшем стеке для всего банка.

**Что происходит при загрузке?** Проверяются размер, расширение, кодировка и заголовки. Далее нормализуются и проверяются строки. Ошибки и дубликаты учитываются отдельно. Принятый набор сохраняется как предварительный; пользователь явно применяет его.

**Почему не заполнять пропуски нулями?** Отсутствующая сумма и нулевой убыток — разные факты. Подстановка нуля сделала бы отчёт правдоподобным, но неверным. Такую строку отклоняем.

**Что означает score?** Сумма весов пяти демонстрационных правил. Это порядок просмотра, а не вероятность ущерба. Критическая активная запись может иметь меньший score, чем запись с несколькими другими флагами; поэтому критические случаи также выделены отдельной кнопкой.

**Что такое outlier?** Для категории с минимум восемью записями считаются квартиль Q1, Q3 и IQR = Q3 − Q1. Значение выше Q3 + 1.5 × IQR помечается, если IQR положителен. Это повод проверить запись, а не доказательство ошибки или мошенничества.

**Почему флаги не меняются от фильтра?** Пороги рассчитаны по всему принятому набору. Фильтр меняет видимую выборку, а не контекст правила. Это обеспечивает стабильность объяснения.

**Где используется AI?** В помощи при проектировании, написании и проверке проекта. Онлайн-анализ не вызывает LLM. Готовая сводка использует фиксированные шаблоны и рассчитанные числа. Не следует называть её нейросетевым прогнозом.

**Что есть по SQL?** Данные хранятся в SQLite с таблицами наборов и инцидентов. В `sql/examples.sql` есть запросы с агрегацией и извлечением полей JSON. Для более сложного проекта стоило бы рассмотреть отдельные типизированные колонки, индексы и миграции.

**Что пришлось бы изменить для реального банка?** Согласованную модель данных, утверждённые правила, полноценную авторизацию, аудит и контроль доступа, безопасный deployment, мониторинг, управление версиями и правила хранения. В учебном проекте эти требования не имитируются заявлениями о production readiness.

## Небольшое самостоятельное упражнение

Скопируй sample CSV. Измени сумму одного инцидента на 10000, другой строки — на `not available`. Загрузи файл с датой 2026-09-24. До применения предскажи:

- Какая строка получит High recorded loss?
- Какая будет отклонена?
- Почему у принятого файла изменится итоговая сумма?
- Сколько исходных и принятых строк останется?

Затем найди функции `parse_money`, `validate_csv` и `enrich`. Проследи один инцидент от CSV до карточки. Это даст больше для разговора, чем заученное описание интерфейса.
